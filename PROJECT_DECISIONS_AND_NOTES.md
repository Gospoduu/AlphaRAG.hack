# 📋 Отчет о разработке и архитектурных решениях: Агентная система поддержки (Tender Hack)

## 1. Контекст задачи и вводные данные
- **Мероприятие:** Хакатон *Tender Hack — Нижний Новгород*.
- **Кейс:** Автоматизация и интеллектуализация клиентской поддержки пользователей **Портала Поставщиков Москвы** (`zakupki.mos.ru`).
- **Стек и исходные репозитории:**
  1. `AlphaRAG.hack` (Backend на FastAPI, Postgres, Redis, Kafka, Web-интерфейс `Back/static/index.html`).
  2. `MAESTRO` (RAG/LLM микросервис, векторный поиск, генерация ответов по регламентам).
- **Ключевые ограничения:**
  - **Слабый ноутбук пользователя:** Категорический запрет на локальный запуск тяжелых ML-моделей (LLM, эмбеддеры). Вся тяжелая аналитика выполняется на удаленном сервере.
  - **Консервация контрактов:** Сохранение структуры WebSocket-событий, REST API и ключей локального хранилища браузера.
  - **Развитие только в нужных ветках:** Работа и выгрузка строго в ветки `dev` и `develop`.

## 3. Архитектурные развилки и инфраструктурные решения

### Проблема с Docker Desktop:
- При попытке запуска контейнеров через `docker-compose.yml` Docker Desktop в Windows выдал сбой: `Docker Desktop is unable to start` / `context deadline exceeded`. Причина — на ноутбуке не был активирован WSL2 / аппаратная виртуализация Hyper-V, а попытка поднять 3 тяжелых контейнера (Kafka с Zookeeper/KRaft, Postgres 17, Redis 7) перегрузила бы слабый процессор и оперативную память.

### Решение: Автономный легковесный сервер `run_local.py`
- Разработан и запущен микросервер на **FastAPI + SQLite + WebSockets**:
  - Потребление оперативной памяти: **~30 МБ** (вместо 4–6 ГБ под Docker).
  - Запуск: мгновенный (0.2 сек).
  - База данных: локальный `local_chat.db` через встроенную библиотеку `sqlite3` (история диалогов, пользователи и сообщения сохраняются между перезагрузками).
  - Web-сервер: Uvicorn слушает порт `8000` и мгновенно отдает интерфейс `Back/static/index.html`.
  - WebSocket: полноценная симуляция генерации токенов в реальном времени (`new_token` с задержкой 20 мс) и финального события `end_generation`.
  - Устранена проблема `ERR_CONNECTION_REFUSED`.

## 5. Текущее состояние и проверка работоспособности

- **Сервер:** Активен на `http://localhost:8000`.
- **Интерфейс:** Доступен в любом браузере.
- **WebSocket:** Активен по адресу `ws://localhost:8000/api/ws/{user_uuid}`.
- **REST API:**
  - `POST /api/user/` — регистрация/авторизация роли.
  - `GET /api/chat/{user_uuid}/chats` — список диалогов пользователя.
  - `POST /api/chat/` — создание нового обращения.
  - `DELETE /api/chat/{chat_id}` — удаление чата.
  - `GET /api/chat/{chat_id}/messages` — загрузка истории сообщений.
